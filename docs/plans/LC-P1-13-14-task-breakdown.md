# LC-P1-13 / LC-P1-14 — The public alpha: evaluation, fault injection, and the handoff

**Gate:** G5 — the public alpha · **Work orders:** 13 (evaluation, fault injection
and a competitor baseline) and 14 (public alpha handoff and review dossier)
· **Status of this document:** the work orders are **NOT STARTED** and this
document does not change that. It says what the gate must produce, what
already exists for it, and which decisions belong to the owner.

**Read this first:** [the work-order board](../PHASE_1_WORKORDERS.md) for the
two work orders' own Build and Acceptance text, and
[`docs/EVALUATION.md`](../EVALUATION.md) for the protocol G5 measures against.
**That protocol is already written** (2026-10-15) and this document does not
replace it.

## 1. Goals and boundaries

### 1.1 What G5 must produce

**One sentence, from the board:** an **outsider** can install LabCairn from
nothing, bind a research folder, get a report and a deterministic figure with
source locators and an evidence ledger, revise it, and reopen the same task
after a restart — with the fault injection showing that a crash does not
repeat an unknown side effect, and with the numbers **measured on named
fixtures** rather than asserted.

**The gate's exit test, from the board's milestone table:** *"outsider fresh
install, 3 fixtures, fault injection, docs and real-provider smoke."*

Five things, and each is a product of a *different* kind of evidence:

| # | What | The evidence that it is true |
|---|---|---|
| 1 | **The outsider's path works from a clean environment** | a **fresh clone** — not the developer's checkout — following the README, with the commands in the README actually run by something |
| 2 | **Three public fixtures with real answer keys** | the fixtures' **source locators, hashes and answers**, checked against the material, and the answers **not** generated by the thing they judge |
| 3 | **Fault injection** | the crash matrix, **run end to end through the surfaces** and not only in the layer's own unit tests |
| 4 | **The documents** | every `uv run` and `pnpm` command in them **is a command a test runs** |
| 5 | **One real provider's smoke** | a real provider under a declared model, version and parameter set, with its cost recorded — **mock-only success is insufficient** |

### 1.2 Already done — removed from scope

**A great deal of G5's material exists.** This is not a gate that starts from
nothing, and the breakdown says so, because the board's rule is that a work
order is marked done when a review says so, and a breakdown that ignores what
is already built is how a gate gets re-done twice.

| What G5 needs | What exists | Where |
|---|---|---|
| **The evaluation protocol** — five mandatory gate classes, the metrics, the denominators, the seven Phase 1 blockers | **written, 2026-10-15** | [`docs/EVALUATION.md`](../EVALUATION.md) |
| **Fixtures with expected outputs** | `tests/fixtures/` in three groups — `analysis/` (21 files: CSV and XLSX with a `*.expected.json` beside each), `papers/`, `retrieval/` | `tests/fixtures/` |
| **A crash matrix** | **eight cases**: AT1 (crash before write — replayable), AT2 (crash after write, before commit — *the only bad case*), AT2b (the write counter as evidence), AT3 (crash after commit, before the receipt — no replay needed), AT3b (a reconnecting client gets exactly the missed events), AT5 (reconciliation detects an absent write), AT6 (reconciliation flags conflicting content for a human), AT7 (the matrix itself, run as a subprocess) | `tests/test_recovery_crash_matrix.py` |
| **An exit demonstration that is run by a test** | `examples/g4_exit_demo.py`, run as a subprocess whose **exit code is the assertion**, with the fault planted from outside | `tests/test_smoke_path.py` |
| **The architecture document** | written | [`docs/ARCHITECTURE.md`](../ARCHITECTURE.md) |
| **The font audit** — what third-party material reaches a user, measured | **done, 2026-10-25** | [`LC-P1-14-font-licence-audit.md`](../acceptance/LC-P1-14-font-licence-audit.md) |
| **A bilingual README's bones** | the title, the tagline and the "not open source yet" notice are already in both languages | `README.md` |

**And the gaps that are known, which is the other half of "already done"** —
the board and the handoff name them, and G5 has to cover them:

- **G1's and G2's work orders have no independent review.** The reviews that
  found their defects and the fixes that answered them were the same party in
  every case, and the board's rule is that a row is marked done when an
  *independent* review says so.
- **G1's and G2's exit demonstrations are run by nothing.** No test and no CI
  job runs `examples/g1_exit_demo.py` or `examples/g2_exit_demo.py`, so they
  can rot without anyone noticing. **The repository says so itself, in two
  places**: `tests/test_analysis_demo.py` and `tests/test_smoke_path.py` both
  open by saying *"Neither `g1_exit_demo.py` nor `g2_exit_demo.py` is run by
  CI or by any test, and that is a hole"* — and the second adds that **G3's
  independent review named it**. LC-P1-10's demonstration **is** covered by a
  test, and G4's by `tests/test_smoke_path.py`.
- **The workbench is never driven against the live service** — its tests use a
  fake at the `fetch` boundary — so *"CLI and UI show identical Task state"*
  is discharged **through the API** rather than measured between the two.
- **The API's event stream is not consumed by the workbench**, and the
  workbench **cannot switch the selected project**, because the API has no
  such operation.

### 1.3 Explicitly NOT in G5

- **No new product capability.** G5 *measures* and *hands over*; it does not
  add a feature. Anything the evaluation finds missing is a **finding for
  Phase 2**, recorded, not fixed inside the gate.
- **No open-source release.** G5 produces the **handoff**; the release is a
  separate act, and it is blocked on §1.4.1.
- **No competitive superiority claim.** `EVALUATION.md` says it plainly:
  results are benchmarks only when measured on immutable fixture and version
  labels, and superiority over PaperQA2 or PaperSpine may not be claimed
  without **like-for-like matched-task baselines**, verified capabilities and
  documented confidence intervals or limitations. **A comparison that is not
  like-for-like is a number in a document, and this repository does not ship
  those.**

### 1.4 The decisions the owner must take, and what each one costs

**These are decisions, not engineering.** Each is stated with what it costs,
because a cost that is not stated is a cost that is discovered later.

#### 1.4.1 The copyright and the root licence

**The facts, measured:** `LICENSE.PENDING.md` says in its first line that it
is not a licence. **Nothing in this repository is licensed to anyone.** The
PyMuPDF decision (ADR-0008) was made *on the assumption* of a permissive root
licence, and the README says the project is *"intended to be released as open
source once the copyright position is settled"*. That position is not
settled.

**The font half of this is measured and it is not the obstacle** — the
[font audit](../acceptance/LC-P1-14-font-licence-audit.md) shows that no
third-party font file reaches any artefact, so the GPL font reportlab bundles
does not attach to what a user receives. **The copyright half is the obstacle
and it is the owner's.**

- **Option A — a permissive licence (MIT), once ownership is settled.**
  *Cost:* nothing beyond the ownership question, and it keeps ADR-0008's
  reasoning intact.
- **Option B — a copyleft licence.** *Cost:* the AGPL question PyMuPDF was
  avoided for comes back in a different place, and the "intended to be
  released as open source" language in the README changes meaning.
- **Option C — no licence yet.** *Cost:* the alpha can still be handed over as
  a *private* preview, and **no public claim of any kind may be made** — which
  is what §1.3's "no open-source release" already says.

#### 1.4.2 Which provider, and whose credential, for the real smoke

**The facts:** `EVALUATION.md` requires *"at least one real supported
provider under declared model/version/parameters; results and costs
documented"*, and the board says the same. The repository has a FakeProvider
and **no** real provider is configured; the `.env.example` and the
`requires_provider` marker exist for exactly this.

- **Option A — a provider the owner already has an account for**, with the
  cost ceiling set in advance. *Cost:* the smoke's cost is real money, and the
  model must be **declared** (name, version, parameters) for the result to be
  a measurement rather than an anecdote.
- **Option B — the owner runs the smoke themselves** and hands the result in.
  *Cost:* the result is then not reproducible by anyone else, which weakens
  the dossier.
- **Option C — skip it.** *Cost:* `EVALUATION.md` says mock-only success is
  insufficient, so this **fails the protocol**. It is not a lesser gate; it
  is a different one.

#### 1.4.3 The competitor baseline's scope

**The facts:** the board asks for a "competitor baseline". `EVALUATION.md`
permits a comparison only on like-for-like matched tasks with verified
capabilities and stated limitations. Running PaperQA2 or PaperSpine over the
same three fixtures is **days of work and a second installation** — and the
same protocol's rule is that a comparison not like-for-like is not a
comparison.

- **Option A — matched-task baselines on all three fixtures.**
  *Cost:* the largest single item in G5, and the most likely to be cut.
- **Option B — matched-task baselines on one fixture, and the other two
  reported without comparison.** *Cost:* the dossier says exactly what was
  and was not compared, and the numbers are **not** presented as a ranking.
- **Option C — no comparison; the dossier states what was measured and what
  was not.** *Cost:* the work order's "competitor baseline" is not delivered
  as a comparison. **This is the option the protocol's own rule points at
  when a comparison cannot be made honestly.**

#### 1.4.4 Whether G1 and G2 get a retro-review

**The facts:** both gates closed on a review by the party that also wrote the
fixes. The board's rule — *"a row is never marked done because something looks
finished; it is marked done when an independent review at a named commit says
so"* — was applied to G3 and G4 and not to G1 and G2.

- **Option A — a retro-review of G1 and G2, with a reviewer who wrote none of
  their fixes.** *Cost:* the reviewers have to break two closed gates, and the
  findings re-open work that was accepted. **That is the honest cost and it is
  the right one.**
- **Option B — record the gap and leave the rows as they are.**
  *Cost:* two rows of the board say "accepted" on evidence that the board's own
  rule does not accept. **This should be stated on the rows, not left
  implicit.**

## 2. The shape of the thing

### 2.1 The protocol decides the metrics; the gate decides the exit

`docs/EVALUATION.md` is the protocol, and it is not to be rewritten by G5.
It names **five mandatory automated gate classes** — unit, integration,
negative, e2e, real-model smoke — and **seven Phase 1 blockers**:

> - A new user cannot complete a task from a clean environment following README.
> - Any unauthorized file write/escape or unconsented private-network disclosure.
> - Fake citation presented as verified or unsupported numerical fact presented as measured.
> - A crash silently repeats unknown file side effects.
> - Report claims a verified scientific result based solely on schema or rendering checks.
> - Required CI tests are skipped, ignored or only pass by mocking the actual behavior under acceptance.

**Those seven are the exit test in prose**, and four of them are the very
shapes this repository's reviews have found: a claim presented as verified, a
crash repeating a side effect, a test that passes by mocking the behaviour it
is supposed to check, and an unwatched mechanism. **G5's own review will look
for exactly these.**

### 2.2 The fixtures: three, and one that must find nothing

**Three public fixtures across distinct genres**, each with source PDFs or
text, tabular data, grounded questions, and **expected artefact checks** —
with **actual source locators, hashes and answer keys**, and the rule that
**generated outputs may not be their own oracle**.

**The fourth fixture is the one that finds nothing.** `EVALUATION.md` lists
"insufficient evidence" among the negative cases, and the board lists a
"negative/no-evidence scenario". A fixture whose honest answer is *"the
material does not say"* is the one that proves the report **abstains** rather
than fabricates — and *"unsupported-claim detection and appropriate
abstention"* is one of the metrics. **A suite with only answerable fixtures
cannot measure abstention, because abstention only shows up where the answer
is not there.**

**The licence of the fixture material is a constraint on the fixture, not a
detail.** The protocol says *"permissively licensed or synthetic, clearly
labelled"*. **Synthetic is allowed**, and a synthetic corpus is the one way to
be certain of the licence — which matters because the copyright question of
§1.4.1 is still open.

### 2.3 Fault injection: the matrix exists, the end-to-end path does not

**The crash matrix is already written and already tested** — AT1 through AT3b,
with AT2 as *the only bad case* (the bytes are on disk and the receipt is not,
so the replay must be blocked and the write counter is the evidence).

**What G5 adds is the surfaces.** The matrix is tested at the layer; G5's
fault injection runs a crash **through the CLI and the service**, with the
task's state on disk, and shows that the surfaces come back to a state the
user can reason about: no repeated operation, no duplicated side effect, and
the report either regenerated from the recovered state or refused with a
reason.

**And the two exit demonstrations nobody runs** (§1.2) are the natural
subjects: G1's and G2's are **stale by construction** — they are the two the
board says "can rot without anyone noticing". Running them, or a test that
runs them, is the cheapest item in G5.

### 2.4 The outsider's path is a *test*, not a paragraph

**The blocker is the first one in the protocol:** *"A new user cannot complete
a task from a clean environment following README."* It is the only blocker
that is about **a person** rather than about the product, and it is the one
that a test suite cannot express directly.

**The way to make it expressible is to make the outsider's path a script that
a CI job runs on a fresh clone** — a clean checkout, a fresh virtualenv, the
README's commands verbatim, a fixture bound, a task created, a report
produced, a revision requested, and a simulated restart. **A README that is
not run is prose, and this repository has spent two gates learning that
prose is not a witness.**

### 2.5 The licence audit is a gate of its own, and its factual half is done

**It is not optional and not deferred** (the hand-off record). The
[font audit](../acceptance/LC-P1-14-font-licence-audit.md) has measured what
reaches a user and found that **no third-party font file reaches any
artefact**. What remains is the owner's decision (§1.4.1) and three
engineering items the audit names: the NOTICE, the board's record, and the
release's own member lists.

## 4. The acceptance mapping

### 4.1 LC-P1-13's own acceptance clause

> **Acceptance:** transparent denominators, scores and failure cases; no
> invented superiority, no skipped blocking tests; forced-restart task
> continuation demonstrated; no unsafe file/network permissions.

| # | Clause | Carried by | The thing that proves it |
|---|---|---|---|
| 1 | transparent denominators | T01 | every metric is reported as *numerator over denominator* with the denominator's own count, and a metric whose denominator is small says so |
| 2 | scores and failure cases | T01 | the failures are **listed**, not averaged away; a run with a failing case publishes the case |
| 3 | no invented superiority | T09 | the comparison is either like-for-like on matched tasks, or **not made**; the dossier says which, and no ranking is printed without the comparison |
| 4 | no skipped blocking tests | T01 | the protocol's blocking tests are **not** skipped — a skip in a blocking test is a failure of the run, not a neutral |
| 5 | forced-restart task continuation demonstrated | T02 | a restart **in the middle of a task**, with the surfaces, and the task continues from what was recorded |
| 6 | no unsafe file/network permissions | T05, T03 | the threat model names every write and every network reach, and the outsider's run is checked against it |

### 4.2 LC-P1-14's own acceptance clause

> **Acceptance:** an external reviewer can start fresh using docs and
> reproduce the canonical task with own provider, or deterministic fixture
> without provider; `uv run` and `pnpm` commands documented and actually
> tested; artifact examples real; commit SHA and …

| # | Clause | Carried by | The thing that proves it |
|---|---|---|---|
| 1 | an external reviewer can start fresh | T03, T06 | the outsider's script runs on a **clean clone** — not the developer's checkout — and the README it follows is the README in the repository |
| 2 | reproduce the canonical task | T00, T03 | the canonical task is a **fixture with an answer key**, and the reproduced report's answers are compared with the key |
| 3 | with own provider, or deterministic fixture without | T04, T03 | both paths exist and are run: the deterministic one in CI, the provider one by the owner (§1.4.2) |
| 4 | `uv run` and `pnpm` commands documented and actually tested | T06, T03 | **every command in the README is extracted and run** — a command that is in the README and is not in the extraction is a failure |
| 5 | artifact examples real | T00, T06 | the examples in the README and the quickstart are **the fixtures' real artefacts**, produced by the code, not drawn by hand |
| 6 | commit SHA and … | T08 | the dossier names the commit, the fixtures' versions and the limits, so a reader can tell what it is reading |

## 5. What these work orders cannot deliver

- **They cannot grant rights.** A licence is the owner's to grant, and until
  it is granted nothing here is open source (§1.4.1).
- **They cannot make the comparison honest if the comparison is not
  like-for-like.** A baseline run on different fixtures, or with different
  capabilities verified, is not a baseline (§1.4.3).
- **They cannot make the evaluation's numbers general.** They are measured on
  **three named fixtures** with **immutable versions**, and they say so. A
  number from three fixtures is a measurement of three fixtures.
- **They cannot make the live-UI claim.** The workbench is still driven
  against a fake at the `fetch` boundary, so *"CLI and UI show identical Task
  state"* stays discharged **through the API** — and the dossier must say so
  rather than let a reader assume two surfaces were compared.
- **They cannot retire G1's and G2's review gap** without the retro-review of
  §1.4.4, and if that option is not taken, **the two rows say so**.
