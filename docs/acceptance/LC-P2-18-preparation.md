### The AGPL question, settled by measurement

The brief (§2) requires the dependency closure be recorded so the license
boundary is auditable, and names the specific risk: whether the default
install pulls the **AGPL-3.0** `packages/paper-qa-pymupdf/` subpackage.

**What the tree declares.** The root `pyproject.toml` lists
`paper-qa-pypdf` (Apache-2.0) as a hard dependency and puts
`paper-qa-pymupdf` behind the **`pymupdf` and `zotero` extras** and the
`dev` group only. `paper-qa-docling`, `paper-qa-nemotron` and
`paper-qa-pypdf` each carry an Apache-2.0 `LICENSE`; `paper-qa-pymupdf`
carries `GNU AFFERO GENERAL PUBLIC LICENSE Version 3`.

**What the installed closure says.** A scan over all installed
distributions' license metadata found **no GPL or AGPL distribution**.
`paper-qa` and `paper-qa-pypdf` report `Apache License` with the Apache
classifier. The AGPL package is not merely unimported — it is absent:
`importlib.util.find_spec` returns `None` for `pymupdf`, `fitz` and
`paperqa_pymupdf`.

**The conclusion, stated as the run's rule.** Installing the root package
**without extras** keeps the AGPL-3.0 subpackage out of the closure, and
that is what this environment does. The run's environment declaration
must preserve it: **do not install the `pymupdf` or `zotero` extra** into
the competitor environment. `openpyxl` (MIT) is the only addition made on
top of the default closure, for the XLSX rendering below.

## 2. The adapter: corpus in, answers out

**The files.** [`tests/evaluation/paperqa_adapter.py`](../../tests/evaluation/paperqa_adapter.py)
is the translation layer; [`tests/test_paperqa_adapter.py`](../../tests/test_paperqa_adapter.py)
is its witness; [`scripts/paperqa_dry_run.py`](../../scripts/paperqa_dry_run.py)
drives the offline dry run and is not imported by any test. The adapter
imports **no paper-qa module** — a case is driven by any
`(question, document) -> answer` callable — so every witness runs in the
repository's own environment, and CI does not need the competitor
installed.

**What it does, and only this.** Three actions: render a fixture into the
text the system ingests; build the one question from the key's structure;
capture the system's output verbatim in an artifact, which scoring reads
against the committed key. It contains no task logic: no question is
rewritten toward an answer, no output is repaired beyond the scorer's
mechanical number parsing, and a system that raises is called **exactly
once** and recorded as a failed case with its stage and reason.

**The genuinely open XLSX choice, and what was chosen.** paper-qa is
PDF/text-first and its office parser (`unstructured`) is an extra this
closure does not install, so a spreadsheet must be rendered. The dumbest
rendering that parses was chosen: the spreadsheet is read cell by cell
and written as the **same comma-separated text its source CSV holds**.
The witness asserts the rendering *is* the source CSV, byte for byte, for
both derived spreadsheets — the translation adds no header, no sheet name
and no annotation.

**One honest loss, recorded.** The CSV distinguishes an empty cell (the
field is present and empty) from an absent field (the row is short);
`holes.csv` and `holes.xlsx` carry different cell inventories in the
corpus. A textual rendering cannot see that difference — the two render
identically — and paper-qa's text-first ingest could not see it either.
The loss belongs to the competitor's input format, not to this
translation.

**Scoring is deliberately asymmetric, in the direction that flatters the
competitor.** Our side answers a structured selection and is scored cell
by cell. A free-text answer cannot be scored that way by any mechanical
rule, so the competitor's score is a **recall**: each expected statistic
must appear, within the key's tolerance, among the numbers anywhere in
its answer. Extra numbers are not penalised, because citing values from
the table is legitimate and a stricter rule would be a rule about prose.
Recall can only raise a competitor's score; the record says so, so a
competitor's advantage is never an artifact of the adapter.

**Refusals are asked but not scored.** The key marks some selections
refused (a header unit the data contradicts, two unit tokens in one
selection). Refusal is a semantic judgement of prose; a mechanical
adapter that claimed to detect it would be inventing a task rule. The
question lists those selections like any other and the score counts only
the statistics the key attaches to `ok` selections and groups.

## 3. The dry run: how far paper-qa goes offline

**The command** (in the isolated environment; no credential is read and
four provider-key variables are removed from the process environment
first):

```
E:/labcairn-local/paperqa-venv-19b47f/venv/Scripts/python.exe scripts/paperqa_dry_run.py --output <outside-the-repo path>
```

**The pipeline each fixture walked.** render → `parse_text` (paper-qa's
own text reader) → `Docs.aadd_texts` with paper-qa's **local sparse
embedder** (no provider) → `retrieve_texts` (local vectors) →
`Docs.aquery` with a stubbed completion model. The stub raises on its
**first** call, which is where a real run would first spend money.

**The result — all eleven fixtures, measured 2026-11-02:**

| Fixture | Rendered chars | Parsed chars | Retrieved texts | Stub calls | Stage reached |
|---|---:|---:|---:|---:|---|
| `basic.csv` | 53 | 53 | 1 | 1 | `answer-boundary` |
| `declared.csv` | 136 | 136 | 1 | 1 | `answer-boundary` |
| `empty.csv` | 12 | 12 | 1 | 1 | `answer-boundary` |
| `groups.csv` | 83 | 83 | 1 | 1 | `answer-boundary` |
| `holes.csv` | 52 | 52 | 1 | 1 | `answer-boundary` |
| `missing.csv` | 49 | 49 | 1 | 1 | `answer-boundary` |

| `numeric.xlsx` | 53 | 53 | 1 | 1 | `answer-boundary` |

- **Every fixture reached the provider boundary.** Nothing failed at
  render, parse, ingest or retrieval; the dry run's stop is the same one
  for all eleven.
- **`provider_calls: 0`** in the run document. The stub records its call
  and raises `STUB-PROVIDER-BOUNDARY (call 1)`; the record also checks
  that the prompt handed to the stub **carries the fixture's own first
  line**, so retrieval produced the fixture's text rather than something
  else.
- **The parse is paper-qa's own**: rendered and parsed character counts
  are equal for every fixture, so the reader changed nothing on the way
  in.

**What the dry run does not measure, and must not be read as measuring.**
The real per-case call fan-out (the brief's cost shape depends on it),
token counts and cost, answer quality, and whether a real model's answer
survives the adapter's recall scoring. Those need the owner's budget and
are the run's first-case calibration (brief §5 clause 9) — not this
record's.

## 4. Registration, and the two expected reds

The new test file is registered in the three places the repository
requires, and the exact state of each was measured:

1. **File marker.** `pytestmark = pytest.mark.unit` — the file declares
   the `unit` marker, and `tests/test_evaluation_harness.py` checks that
   the partition agrees with the markers a file declares.
2. **Gate class.** `tests/evaluation/manifest.py` files
   `test_paperqa_adapter.py` under `("unit", "numeric-extraction")` — the
   clause is the protocol's numerical-extraction phrase, because that is
   the task the adapter translates, and the class is `unit` to match the
   declared marker.
3. **Shards.** `.github/ci-shards.json` names
   `tests/test_paperqa_adapter.py` in shard 4 on **both** platforms,
   beside `tests/test_evaluation_harness.py`.

**The cost entries are deliberately absent, and one check is red because
of it.** The brief's rule — and the repository's — is that shard costs
are measured **on the runner**; a development machine gives a different
answer and a different order. So no cost number was guessed for the new
file, and `tests/test_ci_shard_coverage.py::test_the_recorded_costs_cover_every_test_file`
is expected red until the next runner measurement — the anchoring test's
own docstring says a new file is caught by exactly that check. Measured
on this tree: coverage red, all other shard checks green (listed exactly
once, all named files exist, shard count matches the matrix, job names
distinct, costs still anchored).

The fix is the documented one, after the next runner run:
`python .github/remeasure_shards.py <run-id>`.

**A local-environment note, not a defect of this change.** In a git
worktree the editable install resolves `labcairn` to the main checkout,
so `tests/test_scaffolding.py::test_core_resolves_inside_the_source_tree`
fails **before any change of this branch** and makes the harness's
smoke-run witness fail with it. With the worktree's `src` on
`PYTHONPATH`, `tests/test_evaluation_harness.py` passes 75/75 on this
tree.

## 5. What is not done

- **The re-pin at full clone (brief §2).** The pinned SHA above was read
  from the shallow snapshot; the brief requires, before anything
  executes, a full clone, a resolution of the SHA against the remote, and
  the verified SHA recorded in the side's basis. That is a network act
  against a public remote and a basis document frozen before the run; it
  is not done here.
- **The real-model run, the budget, and the final competitor list.**
  Runtime decisions for the owner (brief §6). Nothing has been requested
  or spent.
- **The per-case call fan-out, token counts and cost.** Not measurable
  offline; the run's first-case calibration measures them before it
  spends the rest.
- **Re-scoring a real answer.** The recall scorer has only been fed
  witness-built answers; its behaviour on a real model's prose is the
  run's to measure.
